# Step 7b (lean): permissions grid, iPhone quick edits, widgets, notifications — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (chosen) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the admin tunes what Patricia may do on the Mac; either of them makes small fixes from an iPhone (categorise, note, quick sort, update a manual balance); home and lock screens show where the pay month stands; Mango nudges about late rent, bills and tax payments.

**Architecture:**
- **Grid:** a BudgetCore `PermissionGrid` model reads and writes `memberPermission` (already synced and enforced by `AccessPolicy` and the Mac's re-validation). The Mac pane is a thin view with Save/Cancel.
- **Quick edits:** the iPhone becomes a `.device` writer like the iPad. Every edit goes through `DeviceWriter` into BudgetCore edit functions the Mac already has (`TransactionEditing`, `BalanceUpdates`). The area (Property or Budget & accounts) is decided by BudgetCore, not by the view.
- **Widgets and notifications:** BudgetCore builds a `WidgetSnapshot` and a notification plan from `HomeSummary` / `PropertyGlance` (the numbers Home already shows), for the device's viewer. The app writes the snapshot into the App Group container and schedules local notifications; the widget extension only reads the snapshot.

**Tech Stack:** Swift 6, GRDB 6.29, SwiftUI, WidgetKit, UserNotifications, XCTest, XcodeGen.

**Spec:** `docs/superpowers/specs/2026-10-27-step7b-lean-design.md` (binding). Cited: `2026-10-22-iphone-app-design.md` §1, §3.8, §4; `2026-10-22-sync-and-access-design.md` §5.1, §6.3, §12; `2026-10-25-sharing-levels-design.md` §2; `2026-10-26-ipad-tenancy-design.md`. Previous plan (style, `DeviceWriter`): `2026-10-26-ipad-tenancy.md`.

## Global Constraints

- **Logic in BudgetCore.** The grid model, quick-edit functions, snapshot builder, notification planner and reconciler, and all copy live in `Sources/BudgetCore`. `App/`, `Phone/`, `Widgets/` and `MangoUI` only call them. `scripts/build-core-ios.sh` stays green.
- **Mac fits 1100×700.** The Settings pane renders inside it with no horizontal scroll.
- **No figure wraps or truncates; names truncate in the middle** (`.lineLimit(1).truncationMode(.middle)`), on Mac, iPhone and iPad. Snapshot runs report 0 wrap violations.
- **Edits save only on Save or an explicit button.** Grid: Save/Cancel. Categorise/note/balance sheets: Save/Cancel. Quick sort: each category button is the explicit save, with an Undo toast. No edit saves on dismiss or on change.
- **Filed SA returns 2020/21–2024/25 never change.** Every phone write goes through `DeviceWriter.writeCheckingFiledYears` with no resolution (a question becomes an inline refusal). Quick edits never bypass it.
- **Tests never touch the real DB (`~/Library/Application Support/Budget`), the Keychain, iCloud or `/Applications`.** Use `TestDatabase` helpers, BudgetDemo and fakes (`FakeCloud`, `TwoPersonHousehold`). The widget store and the notification center are behind protocols with in-memory fakes in tests. No subagent runs `scripts/install-app.sh`.
- **No new CloudKit record types, fields or payload keys; no `SyncSchema.version` bump.** `memberPermission` already syncs. No Production schema deploy.
- **Nothing personal committed** (public repo): no team ID, emails or real names. Synthetic data only ("Person A", "Person B").
- **A lock screen, widget or notification never shows a private account's figures to the other person.** Snapshots and plans are built for the device's viewer (`PhoneViewer`).
- **Build the App target with `xcodebuild`, not just `swift test`,** before a task is done when it touches `App/` or `Phone/` (or `Widgets/`, `project.yml`).
- **Never delete data on a permission change.**
- **Commands** (`S7=/tmp/mango-7b-build`; outside `~/Documents` because of iCloud CodeSign issues):
  - targeted (fix rounds): `swift test --scratch-path $S7 --filter '<Tests>'`
  - full suite, once at the end of each task: `swift test --scratch-path $S7 --parallel`
  - phone build (also builds the widget extension once Task 7 lands): `scripts/build-phone.sh`
  - Mac build: `xcodegen generate && xcodebuild -project Mango.xcodeproj -scheme Mango -configuration Debug -derivedDataPath $S7/dd CODE_SIGNING_ALLOWED=NO build`
  - Mac snapshots: `scripts/render-snapshots.sh --quick --routes <names> --size 1100x700`
  - phone snapshots: `scripts/render-phone-snapshots.sh $S7/snaps --only <routes>` (and `--device ipad` where a task says so)
  - `scripts/check-actor-writes.sh` → "actor writes OK" after any task that writes through a new path.
  - at most 2 building agents at once.
- **Model tags:** **[opus]** = privacy, sync, write path or filed year: most capable model plus a spec+code review. **[sonnet]** = UI or small: quick review.
- **Dropping tasks:** if budget runs out, drop from the end. Tasks 8–9 (notifications) are independent of 6–7 (widgets) except `PhoneOutputSettings`, defined in Task 6; if 6–7 are dropped, Task 8 defines it instead.
