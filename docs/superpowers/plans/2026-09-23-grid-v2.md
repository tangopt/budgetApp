# Budget Grid v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the Calendar grid's real-data slowdown, redesign it to read as a clean spreadsheet (right-aligned numbers, visible borders, frozen category column and month header), remove the now-unused Pay Period mode, and add first-class category groups so related categories (e.g. every "Car" cost) can be seen as one line and expanded into detail.

**Architecture:** All changes are scoped to the Budget grid (`App/Budget/`) and a new Categories management screen (`App/Categories/`). A new `CategoryGroup` model plus a nullable `groupId` on `Category` back the grouping feature. The grid's row rendering is restructured around an explicit, ordered row-kind list so the visual rewrite (Task 3) and the grouping feature (Task 6) share one row-rendering path instead of two.

**Tech Stack:** Swift 5.10, SwiftUI (macOS 26), GRDB, XCTest — same as the rest of this app.

**Spec:** docs/superpowers/specs/2026-09-23-grid-v2-design.md

## Global Constraints

- Numbers are right-aligned with tabular (monospaced) figures.
- The category column and the month-header row stay visible while scrolling the grid in either direction.
- Pay Period mode is removed entirely from the Budget grid's UI — Calendar is the only view. Pay-period *detection* (`PayPeriodDetector`) and its use by the Forecast screen and CSV export are untouched.
- Category groups are first-class (their own table), not a text label. An ungrouped category behaves exactly as every category does today.
- No changes to Import, Forecast, Net Worth, Rules, or Uncategorized screens.

**Interfaces:**
- Consumes: `Transaction`, `Category`, `CategoryType` (existing)
- Produces: `BudgetGridCalculator.calendarTotalsLookup(transactions: [Transaction]) -> [Int64: [Int: [Int: Int]]]` (keyed `[categoryId: [year: [month: minorUnits]]]`); `BudgetGridCalculator.categoryTotalForCalendarMonth(category:year:month:calendarTotals:) -> Int` (signature changed — now takes the lookup, not raw transactions); `BudgetGridCalculator.yearlyTotal(year:categories:calendarTotals:) -> Int` (signature changed — same reason); `BudgetGridViewModel.calendarTotals: [Int64: [Int: [Int: Int]]]` (private, built once in `load()`)

The Calendar grid currently recomputes every cell by filtering the *entire* transaction list from scratch (`categoryTotalForCalendarMonth`'s `transactions.filter { ... }`), and `yearlyTotal` calls that 12 times per category. With real data (1,600+ transactions, ~50 categories, 6+ years) this adds up to tens of thousands of full-array scans per render — the app's actual reported slowness. The fix: build one lookup dictionary in a single pass over `transactions`, once, when data loads; every cell/year/YoY read becomes an O(1) dictionary lookup instead of an O(N) scan.

In `Sources/BudgetCore/Budget/BudgetGridCalculator.swift`, replace `categoryTotalForCalendarMonth` and `yearlyTotal` (leave `categoryTotal`, `periodSummary`, `yearOverYearChange`, `yearsWithData` exactly as they are) with:

```swift
    /// One pass over every transaction, building `[categoryId: [year: [month: minorUnits]]]`.
    /// Built once when data loads; every cell/year/YoY read is then an O(1) dictionary
    /// lookup instead of re-scanning the full transaction list (the grid was doing that
    /// per cell, per render — the real cause of this screen's slowdown with real data).
    public static func calendarTotalsLookup(transactions: [Transaction]) -> [Int64: [Int: [Int: Int]]] {
        var result: [Int64: [Int: [Int: Int]]] = [:]
        for transaction in transactions {
            guard transaction.status == .confirmed, let categoryId = transaction.categoryId else { continue }
            let components = calendar.dateComponents([.year, .month], from: transaction.date)
            guard let year = components.year, let month = components.month else { continue }
            result[categoryId, default: [:]][year, default: [:]][month, default: 0] += transaction.amountMinorUnits
        }
        return result
    }

    public static func categoryTotalForCalendarMonth(category: Category, year: Int, month: Int, calendarTotals: [Int64: [Int: [Int: Int]]]) -> Int {
        guard let categoryId = category.id else { return 0 }
        return calendarTotals[categoryId]?[year]?[month] ?? 0
    }

    /// Net position for the whole calendar year (income − expenses − transfers), signed
    /// the same way `periodSummary`'s `moneyRemainingMinorUnits` is — the headline figure
    /// shown on each year picker chip.
    public static func yearlyTotal(year: Int, categories: [Category], calendarTotals: [Int64: [Int: [Int: Int]]]) -> Int {
        var income = 0, expenses = 0, transfers = 0
        for category in categories {
            guard let categoryId = category.id else { continue }
            let monthlyTotal = (calendarTotals[categoryId]?[year] ?? [:]).values.reduce(0, +)
            switch category.type {
            case .income: income += monthlyTotal
            case .expense: expenses -= monthlyTotal
            case .transfer: transfers -= monthlyTotal
            }
        }
        return income - expenses - transfers
    }
```
