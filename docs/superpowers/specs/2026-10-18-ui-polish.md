# UI polish: audit and plan (2026-10-18)

The user's request: tables are not consistent, things wrap, and the newer screens don't look
or feel as polished as the rest of the app. Make Documents, Missing evidence, Property and
Tax years (with their tabs and sheets) consistent with Dashboard, Budget, Accounts,
Categories, Forecast, Search and Settings; use panels, themes and charts where they help.

This document is Task 1's output: how to look at the UI without anyone's screen or data
(§0), the design language the polished screens already speak (§1), what the new screens get
wrong (§2 cross-cutting, §3 per screen), what to build (§4), and the order to build it in
(§5). Line numbers are as of the harness commit `0b5181b`.

## 0. Seeing the UI: the snapshot harness

```
scripts/render-snapshots.sh <outDir> [--only property,sheet-tax] [--themes classic,midnight,sunset]
                            [--appearances light,dark] [--looks light-classic,dark-midnight]
                            [--scale 1] [--settle 1.6] [--as-of 2026-10-15] [--size 1440x900]
```

- Builds a **snapshot build** of the app (Debug, compiled with `SNAPSHOTS`, bundle id
  `com.personal.budget.snapshots` so no preferences are shared with the installed app) into
  `$SNAPSHOT_SCRATCH/dd-ui.noindex`, builds `MakeDemoDatabase` into `$SNAPSHOT_SCRATCH/spm`,
  writes `<outDir>/demo.sqlite` (+ `Evidence/`), runs the app binary with
  `BUDGET_DB_PATH=<outDir>/demo.sqlite --render-snapshots <outDir>`, then `lsregister -u` the
  build, deletes it and the snapshot defaults (also on failure or interrupt). It stops if
  either build fails. **This script is the only sanctioned way to run the app binary**,
  always on the demo database. `SNAPSHOT_SCRATCH` defaults to `$TMPDIR/budget-snapshots`.
- `<outDir>` is resolved from where the script is run (links resolved, also for parts that
  don't exist yet) and must be new, empty or an earlier output of the script (it keeps a
  `.budget-snapshots` marker); never the app's data folder. `--as-of` is the day the app takes
  as today (`AppClock`; default 15 Oct 2026, the demo's), so the screens don't drift with the
  calendar; `--size` renders at another window size (e.g. `1280x800`) to check narrower
  layouts.
- Output: `<screen>-<tab>-<appearance>-<theme>.png` (1440×900 at `--scale 1`) and
  `index.html`. 70 routes × light/dark × classic/midnight/sunset = 420 PNGs, ~7 minutes.
  `--only` takes substrings of route names (`property-`, `tax_years-income`, `sheet-`), so a
  task can re-render just its screens in under a minute; an `--only` run adds to the folder
  (a full run empties it first) and its `index.html` lists only what it rendered, so render a
  task's before/after into folders of their own (`<scratch>/ui-snapshots/task3-before`).
  `--looks` captures just the appearance–theme pairs it names instead of every appearance in
  every theme.
- **Wrap probe** (`App/Snapshots/WrapProbe.swift`, snapshot builds only): every figure view —
  `figureText()`, `MoneyText`, `DateText`, `FigureTile`, `StatusPill` — reports its rendered
  frame and its one-line ideal size; after each capture the runner collects the figures that
  **wrapped** (taller than one line of their font), were **truncated** (narrower than their
  ideal beyond the shrink they allow) or are **cut off** (outside the window sideways, in
  content that doesn't scroll sideways: the month grids are marked with
  `wrapProbeScrollsHorizontally()`), and writes them by route to `<outDir>/wrap-report.txt`
  (route, view kind, text, shown and ideal size, position, source line) with a two-line summary
  on the console. The report's header also gives the window minimum by screen (the
  `contentMinSize` SwiftUI sets from the view: narrowest, widest, tallest) and the routes
  rendered at their minimum because it exceeds `--size`. The app sets no window minimum of its
  own — the window's minimum follows the screen shown — so the narrow check is
  `--size 1100x700` beside 1440×900 and 1280×800; it must report zero violations at all three.
- Routes (`App/Snapshots/SnapshotCatalog.swift`): every sidebar screen; Search with a query;
  Accounts with Euro Current selected; Documents with a document selected; Missing evidence
  missing-only and all; Forecast's three tabs; Property's seven tabs; Tax years' nine tabs for
  Person A 2025/26 (preparing) plus Rental accounts and Return for 2024/25 (filed); the
  Settings window; and 35 sheets (`sheet-*`, including three polished `sheet-ref_*` sheets to
  compare against).
- Safety: the harness exists only in snapshot builds — the app as built normally (Release,
  the installed app) has no runner, capture or catalog, and a snapshot build refuses to start
  as the app. `--render-snapshots` (`App/Snapshots/SnapshotRunner.swift`) refuses (exit 2)
  unless `BUDGET_DB_PATH` is an absolute file path (no `file:` URI) to an existing file that,
  resolved once (`TaxRegression.resolvedPath`: symbolic links followed, also above parts that
  don't exist yet; compared case-insensitively; hard links caught), lies outside
  `~/Library/Application Support/Budget` and every container's copy, with its `Evidence`
  folder outside them too (`TaxRegression.isAppData`, checked against the real home from the
  user database as well), and carries the demo's `application_id` (`DemoMarker`); the app then
  opens that resolved path only. It refuses an output folder in the app's data too.
  `MakeDemoDatabase` refuses the app's folders, and with `--force` replaces only a database
  with the demo id and an evidence folder holding the demo's marker file (or empty).
  Activation policy `.prohibited` (no Dock icon, no menu bar, never frontmost); the window
  sits far off every screen, can't become key, is `.transient`; no network — the exchange-rate
  refresh, the automatic HMRC rate fetch (`HMRCRateAutoFetch.run`) and the manual one all do
  nothing in snapshot mode; `@AppStorage` goes to a throwaway suite.
- Demo data (`Sources/BudgetDemo/DemoDatabase.swift`, its own target used only by the CLI
  `MakeDemoDatabase` and the tests, never by the app): fully
  invented and deterministic (fixed seed, hand-written PDFs with no timestamps; a test checks
  two builds match). 8 accounts (GBP current, saver, card, ISA, EUR current, EUR mortgage,
  a deposit account left out of net worth, a property valuation), Oct 2023 – 15 Oct 2026 of
  salary, bills, groceries, card payments, transfers (147 linked), a forecast with detected
  recurring items, a reserve, planned items and two scenarios; "Property A" (PT, EUR) owned
  50/50 by Person A and Person B, two tenancies with rent history and deposits, 34 rent
  receipts matched to credits (one late credit left unmatched), three utility providers, 54
  invoices (52 with PDFs, one more PDF waiting for intake), 26 recharge statements (paid, one
  sent and unpaid, one draft), 152 documents (rent receipts, contracts, invoices, notices,
  P60/P11D, HMRC proofs) with 197 links and a few deliberate gaps for Missing evidence; tax
  years 2023/24 paid, 2024/25 filed, 2025/26 preparing/ready, HMRC rates, manual items,
  employments, a benefit, interest, a pension contribution and HMRC payments. `DemoDatabaseTests` checks it builds, is deterministic, and
  that rental accounts, Self Assessment, the property summary and checks run without the
  warnings that mean broken data.
- How a capture is made (`App/Snapshots/SnapshotCapture.swift`): `cacheDisplay` of the
  window's frame view, then the sidebar's Liquid Glass pane drawn separately on a
  sidebar-coloured fill (glass and vibrancy are composited by the window server, which a view
  capture never sees), vibrancy filters dropped, list selections redrawn as plain fills, PDF
  pages drawn directly, scroll-edge blur hidden. A fresh window per route; a warm-up capture
  before the real ones (chart axes lay out on the second pass). Each route loads, then is
  captured in each appearance × theme without rebuilding.
- **Known differences from the real window** (don't "fix" these in the app): the selected
  segment of a *toolbar* segmented control (Forecast's Compare/Differences/Grid) draws without
  its label; the sidebar selection and glass are approximations; sheets are drawn at their
  ideal size on a dimmed canvas, not attached to a window. The window is `--size` unless the
  screen needs more: like the app's window (SwiftUI's `minSize` sizing grows the window to
  the content's minimum as soon as a screen that needs more is shown — checked with a hosting
  view in a 1100-wide window: Documents grew it to 1209, Tax years' Manual items to 1233,
  Missing evidence to 932 tall), it grows to the screen's minimum, and the wrap report lists
  the routes rendered larger. (Until 2026-10-18 the frame was fixed, so such a screen was
  drawn squeezed and cut off at both sides — C6's overflow — which the app never shows.)
  Every screen and sheet now fits 1100×700 (§6.1), so no route renders larger at the three
  sizes.

Every task in §5 renders its screens before and after (`--only`) and attaches the pair. The
baseline for this audit (all 420 PNGs) was rendered from the harness commit into the session
scratchpad's `ui-snapshots/before/`; it isn't committed (regenerate it with the script).

## 1. The established design language

Extracted from Dashboard, Budget grid, Accounts, Categories, Forecast, Search and Settings.

### 1.1 Page structure
- Each screen fills the detail column with content padded **16 pt** (`.padding()`):
  Accounts `App/Accounts/AccountsView.swift:67`, Search `App/Search/SearchView.swift:51`,
  Budget `App/Budget/BudgetGridView.swift:377`, Dashboard `App/Dashboard/DashboardView.swift:73`.
  Blocks stack with **12 pt** spacing (`VStack(spacing: 12)`).
- The screen's name is the window title (`App/ContentView.swift:269`); screens don't repeat it.
- A screen header, when there is one, is a row: key figures left, actions right, the one
  primary action `.borderedProminent` last (Accounts header `AccountsView.swift:185-216`:
  "Net worth · as of" in `.callout` secondary, the figure in `.largeTitle.bold()`, the change
  in `.callout` with `yoyGood/yoyBad`; "Update balances…" bordered, "+ Add account"
  prominent).
- Screen-level verbs that aren't the main action live in the window toolbar as borderless
  icon buttons with `.sharedBackgroundVisibility(.hidden)` and `.help`/accessibility labels
  (Budget grid `BudgetGridView.swift:378`, Categories `App/Categories/CategoriesView.swift:138-139`,
  Rules `App/Rules/RulesView.swift:49-50`).
- A screen with modes puts the mode switch in the toolbar's principal slot (Forecast
  `App/Forecast/ScenarioLabView.swift:42-50`: segmented Compare / Differences / Grid; the
  horizon menu as primary action).
- Responsive pairs: `TwoUpRow` (`DashboardView.swift:88-111`) — two cards side by side at
  equal width when both fit at 340 pt, stacked otherwise; never an adaptive grid with gaps.

### 1.2 Panels and cards
- **Card** = `DashboardCard` (`App/Dashboard/DashboardCard.swift:4-31`): 14 pt padding,
  10 pt internal spacing, `.headline` title with an optional right-aligned "Name ›" link
  (`.buttonStyle(.link)`, `.caption`), `RoundedRectangle(cornerRadius: 12)` filled with
  `theme.surface` **and stroked with `separatorColor`**. The stroke is what makes a card
  visible in Classic light, where `surface` is the same white as the window.
- The Accounts detail panel uses the same recipe (`AccountsView.swift:582-585`).
- Inline banners: Accounts' `Banner` (`AccountsView.swift:308-326`) — icon in the tint,
  `.callout` text, optional "Dismiss", 8 pt padding, `RoundedRectangle(cornerRadius: 8)`
  filled with `tint.opacity(0.1)`.
- Pills: `MainAccountBadge` / `NotInNetWorthBadge` (`AccountsView.swift:833-862`) —
  `.caption.weight(.medium)`, 6×1 pt padding, `Capsule` at 15% of the colour, text in the
  colour (accent) or secondary.

### 1.3 Typography scale
`.largeTitle.bold()` hero figure (one per screen); `.title2.bold()` detail title;
`.title.bold()` detail figure; `.title3.weight(.semibold)` sheet titles (`SheetScaffold`);
`.headline` card and section titles (29 uses); `.subheadline.bold()` year blocks and year
cards; `.callout` secondary lines, banners, side-panel counts (116 uses); `.caption` captions,
table header labels, meta lines (212); `.caption2` chart annotations and hover readouts.
Every number is `.monospacedDigit()`.

### 1.4 Money
- `MoneyText` (`App/DesignSystem/MoneyText.swift:9-46`) is the one way to show an amount:
  `Money.format`, monospaced digits, coloured by sign through `theme.money(_:)`
  (`App/DesignSystem/Theme.swift:158-160`: income positive, expense negative, neutral zero),
  never wraps; in a table column it takes `alignment: .trailing` and may shrink to 70%
  instead of wrapping. `tint:` fixes the colour (`.primary` for totals that aren't gains or
  losses, `.secondary` for muted figures).
- Sign means effect on the user's money: costs are negative (red), income positive (green);
  balances and magnitudes that are neither are `.primary`/neutral. A credit account's debt is
  "£81.47 owed" in expense colour (`AccountBalanceText`, `AccountsView.swift:806-830`).
- **The rule, as `MoneyRole` (`MoneyText(role:)`, task 1):** `.signed` (default) for amounts
  given with their sign (transactions, net, profit, cash flow); `.cost` for a cost given as a
  positive magnitude — **in a money table, a figure strip or a total it shows negative, in
  the expense colour** (a refund, negative, reads as a gain); costs never show in the income
  green. `.neutral` for figures that are neither gain nor loss (balances, prices, deposits,
  the loan, amounts on a document such as a receipt or a statement line, values to copy into
  a form such as SA boxes and P60 figures) **and for the parts of a breakdown in which every
  row is a cost** (costs by category, a tax line's sources, the bills coming up, overdue
  recurring costs) — red on every row would say nothing. Every amount column of a row uses
  the row's role (native, pound items, GBP alike).
- Compact contexts use whole pounds (`DashboardFormat.pounds`, `App/Dashboard/DashboardFormat.swift:25-27`);
  chart axes use `DashboardFormat.axisThousands` ("£2.5k").
- A non-GBP amount shows its native figure with the GBP equivalent beneath in `.caption`
  secondary (Accounts list rows `AccountsView.swift:412-424`).

### 1.5 Tables and grids
Three established table styles, each consistent within itself:
1. **The month grid** (Budget, Forecast grid): label column 220 pt + 8 pt padding
   (`App/DesignSystem/GridRowLabels.swift:24-30`), rows **28 pt** high with a 1 pt bottom
   separator, a 3 pt leading stripe in the row type's colour (`theme.stripe`), alternate rows
   shaded `theme.rowBackground(shaded)` (`Theme.swift:140`); value columns 120 pt + 2×8 pt
   (`GridMetrics`, `App/DesignSystem/FrozenHeaderScroll.swift:80-89`), right-aligned
   `MoneyText`, 1 pt column separators (`monthSeparator`); a frozen header row in `.headline`
   on `theme.gridHeaderBackground` (`BudgetGridView.swift:257-311`); section rows tinted
   `sectionHeaderTint` with `.caption` labels; group rows `groupRowTint`; totals
   `totalsTint`/`totalsNetTint` (`TotalsRowLabel`, `GridRowLabels.swift:57-66`).
2. **The native list table** (Search, Rules): SwiftUI `Table` with per-column
   `.width(min:ideal:max:)`, dates `.monospacedDigit()`, amounts
   `MoneyText(alignment: .trailing)`, a narrow trailing column for the row's icon action
   (pencil), alternating rows, `contextMenu(forSelectionType:)` with a primary action, an
   overlay message when empty, and a summary bar beneath (`SearchView.swift:103-140`).
3. **The summary table** (Forecast Compare, `SummaryTable` `App/Forecast/CompareTab.swift:198-297`):
   a `Grid` per block under a full-width strip in `theme.sectionHeaderTint`
   (`.subheadline.bold()`), a header row in `.caption` secondary, `Divider`s, a leading text
   column and trailing amount columns of a shared minimum width (120 pt), amounts right-
   aligned in their frames (`amount(_:)`, `CompareTab.swift:277-282`).
- Lists of records (Accounts) are `List(.inset(alternatesRowBackgrounds: false))` with
  two-line rows (name over caption; figure over GBP equivalent), section headers carrying the
  subtotal (`AccountsView.swift:350-387`, `390-429`).

### 1.6 Side panels and inspectors
- `TransactionsSidePanel` (`App/DesignSystem/TransactionsSidePanel.swift:74-129`): 12 pt
  padding on `theme.windowFill`; `.headline` title with + and ✕ (Esc); a `.callout`
  secondary count/total row; a `List` with sections; rows: description over a `.caption`
  meta line, amount trailing.
- Category distribution panel (`App/Categories/CategoryDistributionPanel.swift`): donut plus
  legend rows with amount and percentage.
- The account detail card (above). Documents' inspector is the one place using `GroupBox`
  (`App/Documents/DocumentInspector.swift:135, 248, 317`).

### 1.7 Sheets
`SheetScaffold` + `SheetForm` (`App/DesignSystem/SheetScaffold.swift`): 20 pt padding,
12 pt spacing, min width 420 (`SheetMetrics`, lines 5-14), `.title3` semibold title,
`.callout` secondary subtitle, inline red error, footer with Cancel left and the prominent
default action right (lines 41-136); forms are a two-column grid, labels trailing, controls
leading and filling (`SheetForm`, 142-168), captions via `SheetFormNote`/`sheetFieldNote`.
Steppers show their value as text beside a label-hidden stepper (`IntervalStepper`,
`App/Budget/PlannedItemSheets.swift:701-713`) because `SheetForm` hides control labels.

### 1.8 Colour tokens
From `Theme` (`Theme.swift:13-51`), never literals: `income`, `expense`, `neutralMoney`,
`transfer`, `reserved`, `pending` (amber "to do" state), `yoyGood`/`yoyBad`, `accent`,
`surface` (cards), `windowBackground`/`windowFill`, `gridHeaderBackground`, `rowStripe`,
`groupRowTint`, `sectionHeaderTint`, `totalsTint`, `chartSeries` via `theme.series(n)`.
Status icons on the polished screens are `exclamationmark.circle.fill`/`checkmark.circle.fill`
in orange/green (`App/Dashboard/SmallCards.swift:75-83`); the newer screens already use
`theme.pending`/`theme.income` for the same — the tokens should win.

### 1.9 Charts
Swift Charts throughout. Series colours from `theme.series(n)` or money tokens; area at
0.12 opacity under a 2 pt line; forecast dashed `[5, 4]`; "Today" as a dashed secondary
`RuleMark` with a `.caption2` annotation; hover through `chartXSelection` with a rule and a
readout box (`theme.windowFill`, corner 6, secondary 0.3 stroke); leading Y axis with
`axisThousands` labels; yearly X stride (`App/Dashboard/NetWorthLineChart.swift:34-88`);
forecast bars hatched (`HatchPattern`, `App/Dashboard/YearOverYearChart.swift:42-47`);
donuts as `SectorMark(innerRadius: .ratio, angularInset: 1)` with the legend hidden and a
custom legend list (`CategoryDistributionPanel.swift:202-209`). Charts sit inside cards at
200–230 pt (sparklines 90 pt, axes hidden).

### 1.10 Spacing, icons, empty states, buttons
- Spacing steps: 2/4 (caption under text), 6 (list rows), 8 (controls in a row), 12 (blocks,
  sheet spacing, side-panel padding), 14 (card padding), 16 (screen padding), 20 (sheet padding).
- SF Symbols only; category glyphs via `CategoryBadge`; document counts via a paperclip.
- Empty states: a whole screen uses an icon (`.largeTitle`, secondary), a `.title3` line, a
  `.callout` secondary sentence and one prominent button (Accounts `AccountsView.swift:262-276`);
  `ContentUnavailableView` where the system one fits; inside a card, one `.callout` secondary
  sentence (Dashboard cards, `SmallCards.swift:13-15`).
- Buttons: one prominent action per header or sheet; secondary actions bordered; row actions
  are icons (pencil, ✕, ellipsis menu) or a context menu, not repeated words; navigation
  links "Name ›" in `.link` style.

## 2. Cross-cutting problems in the new screens

**C1 — Panels disappear in Classic light.** `PropertySection` (`App/Property/PropertyView.swift:170-195`)
fills `theme.surface` with corner 8 and no stroke; in Classic light that is white on white, so
every Property and Tax years "section" is invisible and the page reads as loose text
(`property-overview-light-classic.png` vs `property-overview-light-sunset.png`). It's also a
second card recipe (corner 8, padding 12) beside `DashboardCard` (12/14) and `GroupBox`.

**C2 — Screen padding 12 instead of 16.** Property (`PropertyView.swift:34`), Tax years page
(`App/Tax/TaxYearsView.swift:122`), Documents list (`App/Documents/DocumentsView.swift:98`).
Missing evidence (`App/Documents/MissingEvidenceView.swift:37`) uses 16 — and then gets 12
more when embedded in Tax years (double padding).

**C3 — Tables are hand-built `Grid`s with no shared style.** Each block sizes its own
columns, so figures don't line up between blocks of the same page (Money tab's figures vs
costs, `App/Property/PropertyMoneyTab.swift:67-117`; Return tab's box groups,
`App/Tax/TaxReturnTabs.swift:15-37`); headers vary (caption secondary, sometimes a
divider, never a strip); no row separators or zebra on long tables (receipts, statements,
rent by month); tables stop short of the card's width; long tables (24–36 rows) have no
totals row.

**C4 — Rows lose a cell and shift.** `DocumentCountBadge` (`App/Documents/EvidenceSupport.swift:41-58`)
renders nothing when the count is 0; inside a `GridRow` that drops a cell, so later cells
move one column left. Visible in `tax_years-filing-light-classic.png` (the 30 Jul payment's
"Edit…" sits under the 28 Jan payment's paperclip): `HMRCPaymentsGrid`
(`App/Tax/TaxIncomeTab.swift:245-268`, its badge at `:258`; shown on Filing by
`App/Tax/TaxReturnTabs.swift:166` and on Income by `TaxIncomeTab.swift:220`). Same pattern: manual items (`App/Tax/TaxManualItemsTab.swift:36`),
other income (`TaxIncomeTab.swift:175`), pensions (`TaxIncomeTab.swift:200`).

**C5 — Money colours don't follow the sign rule.** `PropertyMoney` without `neutral`
(`PropertyView.swift:197-208`) colours positive magnitudes green, so costs read as gains:
"Total expenses" in the same green as the rental income and the profit on Rental accounts (`App/Tax/TaxAccountsTab.swift:108-116`,
`tax_years-rental_accounts-*`), each cost source green in the line-sources sheet
(`sheet-tax_line_sources-*`), recharge statement totals green (`sheet-recharge_statement_*`).
Elsewhere everything is `neutral` (Return, Calculation, Income), so the same kind of figure
is green on one tab and black on the next.

**C6 — The Tax years page is wider than the window.** The nine-segment `Picker` is
`.fixedSize()` (`TaxYearsView.swift:148-154`) beside a 280 pt list (`TaxYearsView.swift:20`):
the page needs roughly 1,650 pt. At 1440×900 the split view squeezes the sidebar to a sliver
and the Status picker and the Export segment are clipped (`tax_years-*-light-classic.png`).
Property's seven segments plus the period picker fit, just.

**C7 — Mode switches and toolbars are placed three ways.** Forecast's tabs are in the toolbar
(principal); Property's and Tax years' are segmented controls inside the content. Embedded
`MissingEvidenceView` adds its Rules… and Export checklist… buttons to the Tax years window
toolbar while that one tab shows (`tax_years-missing_evidence-*`), so the toolbar changes
from tab to tab while the page's own actions stay in the content. Property and
Tax/Documents action rows are rows of 3–4 bordered buttons (`App/Property/PropertyTenanciesTab.swift:43-50`)
with no primary.

**C8 — Repeated words as row actions.** "Transactions…" on 25 rows of Money
(`PropertyMoneyTab.swift:79-85, 109-111`), "Copy"/"Why?" on every Return box
(`TaxReturnTabs.swift:23-32`) and filing value, "Edit… Delete…" on every income row
(`TaxIncomeTab.swift:232-241`), "Open… / Unlink / Reopen" on statements
(`App/Property/PropertyRechargesTab.swift:211-233`). They wrap, crowd the figures and read as
grey text (borderless) rather than controls.

**C9 — Duplicated building blocks.** Three copies of the search field
(`SearchView.swift:80-99`, `DocumentsView.swift:101-119`, `MissingEvidenceView.swift:169-187`;
`LinkEvidenceSheet` uses a plain rounded field instead); four banners (`PropertyBanners`
`PropertyView.swift:142-166`, `TaxBanners` `TaxYearsView.swift:215-242`, Missing evidence
`MissingEvidenceView.swift:199-210`, Accounts `Banner`); filters as pop-up buttons on
Documents (`DocumentsView.swift:233-292`) vs chips with chevrons on Search
(`App/Search/SearchFilterBar.swift:100-125`, private).

**C10 — Ragged text columns.** Dates are variable-width text in rows that should line up:
Calendar and "Coming up" (`PropertyObligationRow`, `PropertyView.swift:356-374`), line
sources (`sheet-tax_line_sources-*`), checks (`PropertyView.swift:447-457`). The Profile
tab's role pickers start wherever each account name ends (`App/Property/PropertyProfileTab.swift:78-90`).

**C11 — Steppers hide their value.** `SheetForm` hides control labels, and the tenancy
form's steppers carry their value in the label, so "Advance rent" and "Deposit" show bare
arrows (`App/Property/PropertySheets.swift:333, 336`; `sheet-tenancy_form-*`). Same for
"Cover if unknown" (`App/Tax/TaxSettingsTab.swift:271`).

**C12 — Status as plain words.** Statement status "Paid / Sent 3 Sep 2026 / Draft"
(`PropertyRechargesTab.swift:207, 250-256`), receipt "Issued/Cancelled"
(`PropertyTenanciesTab.swift:200`), tax year status in the list (`TaxYearsView.swift:79-83`)
— where Accounts uses pills.

**C13 — Empty and OK states are bare.** "None." under each Checks heading
(`PropertyView.swift:424-501`) gives no sense of "all good"; statements' line area is a
blank box when there are no lines (`sheet-recharge_statement_*`); the intake sheet's
provider list truncates ("Example Wa…", `sheet-invoice_intake-*`).

**C14 — No charts where the data is a series.** Rent by month (12 rows,
`TaxAccountsTab.swift:36-55`), Money's monthly table (8 columns × 12 rows,
`PropertyMoneyTab.swift:119-149`), 26 statements, the SA110 steps, the evidence progress — all
tables of numbers with a visual story, against an app whose polished screens chart the same
kind of data.

## 3. Per screen

PNG names are from `scripts/render-snapshots.sh`; `*` = every appearance/theme.

### Documents (`documents-main-*`, `documents-selected-*`)
- Filters are two rows of pop-up buttons (`DocumentsView.swift:233-292`) in a different style
  from Search's chips; they wrap at the list's 280–520 pt width.
- List rows are two lines with the paperclip far right; 152 documents in one flat list, no
  grouping by year or kind, no count by kind (`DocumentListRow`, `DocumentsView.swift:191-231`).
- The detail column is 900 pt of empty state until something is selected; with a selection,
  the inspector's `GroupBox`es (`DocumentInspector.swift:135-347`) are a third panel style.
- Toolbar: two icon-only buttons (add, folders) — fine, but the add button is the screen's
  main action and has no label.
- Search field: the third copy (C9).
- "Suggested transactions" rows put a Link button on every row with a 2–3 line caption
  (`documents-selected-*`): heavy for a list of candidates.

### Missing evidence (`missing_evidence-main-*`, `missing_evidence-all-*`)
- Rows are four lines (title, meta, "Needs …", status) with amount and two controls on the

## 4. Proposal

### 4.1 Shared components (new, in `App/DesignSystem`)
1. **`Panel`** — the card recipe as one component: title (`.headline`), optional subtitle,
   accessory (trailing; buttons or a "Name ›" link), content; padding 14, corner 12,
   `theme.surface` + `separatorColor` stroke. `DashboardCard` becomes a thin wrapper;
   `PropertySection` is replaced. Optional `.compact` (padding 12) for side panels.
2. **`DataTable`** — a declarative table for record lists and figure tables, rendered as a
   `Grid` (so it scrolls with the page and sizes to content) with one style:
   - columns: `.text(title, width:)`, `.date` (as wide as `DateText`, the widest day in
     monospaced digits), `.money(currency or per-row, role: .signed/.cost/.neutral)`
     (right-aligned `MoneyText`, min 96 pt),
     `.status` (pill), `.badge` (document count; always occupies its cell — fixes C4),
     `.actions` (trailing icon buttons / ellipsis menu, never words);
   - header row: `.caption` secondary on a `theme.gridHeaderBackground` strip with a bottom
     divider; rows 28 pt with 1 pt separators and optional zebra (`theme.rowBackground`);
     optional group strips (`sectionHeaderTint`, `.subheadline.bold()`, like `SummaryTable`)
     and a totals row (`totalsTint`, semibold);
   - column widths shared across the table's groups (fixes C3 within a page: one table with
     groups instead of several grids).
   `SummaryTable` is the model; Search/Rules keep native `Table` (selection, sorting).
3. **Money semantics** (`MoneyRole`, §1.4) — `PropertyMoney` goes; callers say what an
   amount is: `.signed` (gain/loss, coloured by sign), `.cost` (a magnitude shown negative in
   red in money tables, strips and totals), `.neutral` (balances, document and form figures,
   and breakdowns where every row is a cost). Fixes C5. `FigureTile`'s `gbp` is the
   native-over-GBP pattern.
4. **`FigureTile` / `FigureStrip`** — title (`.caption` secondary), value (`.title3`
   semibold `MoneyText`), optional GBP and caption; a strip lays out 3–7 tiles in equal
   columns with dividers (Overview key figures, Calculation, Recharges, Missing evidence).
5. **`InlineBanner`** — Accounts' `Banner` promoted: info / success / warning / error with
   theme tokens, dismissible; replaces `PropertyBanners`, `TaxBanners`, Missing evidence's
   banner and the "To look at" section.
6. **`SearchField`** and **`FilterChip`** — the Search screen's field and `FilterButton`
   made shared; Documents, Missing evidence and the link sheets use them.
7. **`StatusPill`** — `.caption.weight(.medium)` capsule in a tone: `.neutral` (draft,
   cancelled, preparing), `.accent` (sent, ready), `.positive` (paid, filed, done),
   `.warning` (missing, overdue, not matched), `.negative` (a mismatch); used for
   statements, receipts, tax year status, checks.
8. **`ValueStepper`** — `IntervalStepper` generalised (value text + label-hidden stepper);
   fixes C11.
9. **`ScreenTabs`** — one way to switch a screen's sections in the content (Forecast keeps
   its toolbar control): a segmented control with every section when they fit, otherwise
   the first ones that fit and a "More" menu (showing the chosen section's name while it's
   one of them) instead of forcing width (fixes C6). Property (7) and Tax years (9) use it.
10. **Charts** (`App/DesignSystem/Charts/`): `MonthlyFlowChart` (bars in and out per month,
    net line, hover readout, today rule, `axisThousands`-style labels in the property's
    currency), `BalanceLineChart` (Accounts' sparkline style, with axes when large),
    `WaterfallChart` (start, steps up/down, subtotal bars, end; money tokens), `ProgressRing`
    (done/total with the percentage inside; theme accent, income when complete), and a
    `BreakdownBars` horizontal bar list (label, bar, amount, share) — the Categories
    distribution's legend style as a chart.
11. **`DateText`** — fixed-width, monospaced day text for list rows (fixes C10).

## 6. Design system usage

Which shared piece does which job, so new screens stay consistent. Everything is in
`App/DesignSystem` unless named otherwise; `gallery-components` and `gallery-tables`
(snapshot builds) show them in every theme.

### 6.1 Page
- **Padding and spacing**: `ScreenMetrics.padding` (16) around a screen, `ScreenMetrics.spacing`
  (12) between its blocks. The window title names the screen; a page header (title or
  figures left, actions right, the one prominent action last, the rest in a `More` menu)
  only when the screen has a selection or actions of its own.
- **Fits a 1100×700 window**: a screen's minimum (the window can't be smaller while it shows)
  stays within 1100×700, so it never forces a bigger window than a small laptop has; the wrap
  report's "Window minimum by route" shows it. SwiftUI measures a minimum at the narrowest
  width, where every fallback has stacked (`TwoUpRow`, `FigureStrip`, `ViewThatFits`), so a
  page whose panels stack when narrow sets the width it's measured at
  (`.frame(minWidth:)`, as Missing evidence does: 932 pt tall before, 382 after); let long
  content scroll; give a table's labels `.fill(min:)` columns that truncate rather than fit
  columns; keep a native `Table`'s ideal column widths within its pane at that size (it starts
  them at their ideals and only widens them); prefer an `HStack` to an `HSplitView` (Documents':
  its minimum was its panes' plus 145 pt).
- **Sections of a screen**: `ScreenTabs` in the content (never wider than the page; a More
  menu takes the rest). Only Forecast keeps its segmented control in the toolbar.
- **Toolbar**: screen-level verbs that aren't the main action, borderless with
  `.sharedBackgroundVisibility(.hidden)`, `.help` and an accessibility label; the main
  action (Add documents…, New property) labelled.
- **Rows of panels**: `TwoUpRow` (`App/Dashboard/DashboardView.swift`; two equal panels,
  stacked under 340 pt each), `SplitRow` (a ratio, stacked below `stackBelow`), `PanelGrid`
  (equal columns of panels, as many as fit). Give panels in a row `fillsHeight: true`. Under a
  page header that already takes height, prefer a plain side-by-side `HStack` with
  `.fixedSize(horizontal: false, vertical: true)`: the window's minimum height is measured
  with every fallback at its narrowest.

### 6.2 Containers and messages
- **`Panel`** for every card: `.headline` title in sentence case, a `.caption` subtitle with
  no full stop, an accessory (small bordered buttons, a `PanelLink` "Name ›", a pill or
  pencil/••• icons) and the content. No `GroupBox`, no hand-made rounded rectangles.
- **`InlineBanner`** (info, success, warning, error) for a message inside a screen; in a
  sheet the error is `SheetScaffold(error:)` (`SheetErrorText`).
- **Empty**: `EmptyState` (icon, title, sentence, actions) with `.fillingScreen()` for a
  whole screen or `.inPanel()` inside a panel; `SheetEmptyState` for a sheet's empty area; a
  panel whose list is empty says one `.callout` secondary sentence, "No … yet: what to do.";
  `ContentUnavailableView` where the system's fits (no search results, nothing missing).

### 6.3 Figures and tables
- **`FigureTile` / `FigureStrip`** for 3–7 headline figures (money with its role, the GBP
  equivalent beneath, a caption, a pill for a check on the figure).
- **`DataTable`** for records and figure tables inside panels and sheets: `.text`, `.date`,
  `.money(role:)`, `.status`, `.documents`, `.actions` columns; `DataTableSection` groups
  with totals; zebra by default (`zebra: false` for short tables); actions as icons and a •••
  menu (`DataTableAction`), never words. A native `Table` only for long, selectable,
  sortable lists (Search, Rules, Documents' library). A table that scrolls inside a sheet
  gets `.sheetListFrame()`.
- **`MoneyText(role:)`** for every amount: `.signed` (as given), `.cost` (a cost given as a
  magnitude: negative, in the expense colour), `.neutral` (balances, document and form
  figures, all-cost breakdowns); `wholeUnits` for figures the return takes in pounds.
- **Figures never wrap** (a figure is any amount, number, percentage, count, rate, date, period,
  year or box value). Amounts are `MoneyText` (never `Text(Money.format(…))`); a day in a
  row is `DateText`; any other figure in a `Text` takes **`.figureText()`** — one line at its
  natural width, so the layout around it gives way (a label beside it truncates, a column
  flexes) — or `.figureText(.shrink())` where its width can't give way (a fixed grid column, a
  donut's centre: it shrinks to 70% before it would truncate, and the probe reports it if it
  does). A line that is a label plus a figure is split so only the label truncates
  (`DocumentCaptionLine`, "Name · " + the day). A sentence that holds figures may wrap as
  prose, but never through a figure: put the figure in with `String.unbroken` (BudgetCore;
  no-break spaces, a word joiner after a sign or dash), or pass prose made elsewhere through
  `figuresUnbroken` (days, signed amounts, ranges). `FigureTextRuleTests` fails on a
  `Text(Money.format(…))` and on a `Text` of a formatted figure (`Money.format`,
  `DashboardFormat.pounds/percent/day/monthYear`, `DocumentFormat.day`, `PayMonthFormat`,
  `String(format:)`, `.formatted(…)`) without `.figureText()` or `unbroken` in its statement;
  the wrap probe checks what renders.
- **`DateText`** for days in rows; **`StatusPill`** for a state: `.neutral` (draft,
  preparing, cancelled, not due yet), `.accent` (sent, ready, in force, a tax deadline),
  `.positive` (paid, filed, done, matches), `.warning` (missing, overdue, part paid, not
  matched, no proof or PDF, short), `.negative` (a mismatch or an error).

### 6.4 Controls
- `SearchField` and `FilterChip` / `FilterPickerChip` for search and filters; `CopyValueButton`
  for a value to copy; `DocumentCountBadge` (`App/Documents/EvidenceSupport.swift`) for a
  record's documents (a dashed circle in the pending colour when one is expected);
  `ValueStepper` for a stepper in a form; `NamedCheckbox` for a checkbox in a `SheetForm`.
- Sheets: `SheetScaffold` + `SheetForm` at one of `SheetMetrics`' widths (compact 420, form
  520, list 640, table 860, workspace 1040 — narrower than a 1100-wide window); Cancel left,
  the prominent action right.
- Icons: edit `pencil`; delete a record (asks first) `trash`; remove or unlink from a list
  (the record stays) `xmark.circle`; remove a row of the form being edited `minus.circle`;
  more `ellipsis.circle`; show where it lives `arrow.right.circle`; open a document
  `arrow.up.forward.square`; drill down `chevron.right`; add a document `doc.badge.plus`;
  link `link` / `link.badge.plus`; export `square.and.arrow.up`. Every icon-only button has a
  `.help` and an accessibility label naming its object ("Edit Tenancy 2").

### 6.5 Charts and colour
- `MonthlyFlowChart` (in above the axis, out below, net as a line; today rule; hover),
  `BalanceLineChart` (a balance over time; `showsAxes` off for a sparkline), `WaterfallChart`
  (how a figure builds up), `BreakdownBars` (parts of a whole, money or counts, with
  chevrons), `ProgressRing` (done of total). Month axes abbreviated ("Jan"), amounts with
  the currency in thousands ("€2k").
- Colours from `Theme` only: money tokens for in and out, `theme.series(n)` for categories,
  `theme.chartAccent` for what's drawn beside money colours (a net line, totals),
  `theme.pending` for to-do, `theme.accent` for text and marks. The root tints controls with
  the accent; a control that puts white text on the accent fill (a `.borderedProminent`
  button, a segmented picker) adds `.prominentTint()` (`theme.controlAccent`); set no other
  `.tint`. Check Classic light, Midnight dark and Sunset light, and run `--themes` with all
  fifteen for anything with new colours.
